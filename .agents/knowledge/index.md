# Knowledge index

Load a pattern when its trigger applies. These files preserve useful rationale
and rejected approaches; [Docs/README.md](../../Docs/README.md) identifies standing
policy owners. They are not a second policy layer or required prereads for every task.

| Pattern | Trigger |
| --- | --- |
| [Artwork working set](patterns/artwork-working-set.md) | Launch art, pinning, cache budgets, hitch or memory work |
| [Module DAG and hubs](patterns/module-dag-containment.md) | New dependencies, hub growth, cross-package moves |
| [Deferred seams](patterns/architecture-deferred-seams.md) | Package splits, platform sync, further Battle presentation boundaries |

Keep a lesson only when its evidence and rationale will change a future decision.
Link to the enforcing policy or code instead of copying its rules. Update or remove
stale lessons with the owning change; one-off failures and completed task history
belong in session or Git history. A resolved friction entry does not automatically
need a knowledge file, skill update, or promotion record.

[Representative evals](../evals/README.md) can check consequential workflow changes.
