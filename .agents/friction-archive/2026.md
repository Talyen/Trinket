## Details

### Simulator attachment recheck

- **Context:** 2026-09-19, Xcode 27.0 (27A266a); managed `run-simulator.sh --isolate --inspect`
  built and launched Debug `com.ryanmcintire.Trinket` on Trinket Agent 1,
  UDID `0397DDB0-03A4-46E9-ADA0-1D9F90583D29`, PID `17837`.
- **Evidence:** `ps` confirmed the live PID's executable belonged to that device's
  app container before and after the PID attempts. The wrapper with `--attach
  17837 --time-limit 3s` and direct host `xctrace record --template 'Time Profiler'
  --attach 17837 --time-limit 3s --no-prompt` both exited 21 with
  `Cannot find process for provided pid: 17837`. The same template with
  `--attach Trinket` exited 19 with `Cannot find process matching name: Trinket`.
  Each command supplied a distinct `/tmp/trinket-friction-*.trace` output path.
- **Disposition:** No usable capture obtained; no wrapper change justified.
  Inspection ended normally and released its lease. Sampled stacks remain CPU
  leads, not render-hitch evidence, as the playbook already explains.
- **Closure:** Archived as a documented tooling limitation. The
  [playbook](../../Docs/Platform/PerformanceInvestigationPlaybook.md#investigation-loop)
  records the failed route and fallback evidence limits; restoring Simulator
  attachment is not a prerequisite for closing this friction item. Revisit only
  when profiling needs it or after a toolchain change. Physical-device evidence
  remains documented in the [playbook](../../Docs/Platform/PerformanceInvestigationPlaybook.md#unresolved-device-evidence).
